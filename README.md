# Avito Listing Monitor

Сервис сверяет клиентскую цену и технический `Id` в автозагрузке Avito. Проекты добавляются через конфигурацию. Сервис хранит результаты сверки, инциденты, историю попыток отправки и резерв ID в SQLite. Перенос цены остаётся задачей действующей интеграции.

| Цена в однозначно сопоставленной строке | Технический Id | Результат |
| --- | --- | --- |
| Положительная | Есть | Штатное состояние |
| Положительная | Пуст | Нужна выкладка |
| Ячейка действительно пуста | Есть | Убрать из выкладки |
| Ячейка действительно пуста | Пуст | Штатное состояние |
| Ноль, формула с пустым результатом, текстовый маркер, ошибка чтения или нет однозначной пары | Любой | Диагностика |

Серверная служба регулярно читает таблицы, обновляет открытые случаи и отправляет утреннюю сводку в один Telegram-чат. Для разрешённого проекта автоматическая операция сохраняет исходный `Id`, повторно сверяет цену и ячейку, очищает её и проверяет статус конкретного объявления через API Avito. При прямой проверке XML не участвует. Журнал хранит подтверждение очистки и отдельно фиксирует результат на площадке.

Автоочистка по умолчанию выключена. Для её включения нужны полностью сверенный проект, пределы удаления, права Google на конкретную целевую таблицу и доступ к статусу объявлений. Порядок включения описан в [инструкции эксплуатации](docs/operations.md).

## Проверка на учебных данных

Нужны Python 3.9+ и UNIX с поддержкой блокировки файлов. Учебные данные и команды ниже работают без аккаунтов и сетевых запросов.

```sh
python3 -m unittest discover -s tests -v
python3 -m avito_monitor --config examples/config.json --db state/demo.sqlite --fixture examples/fixture.json check
python3 -m avito_monitor --config examples/config.json --db state/demo.sqlite --fixture examples/fixture.json report
python3 -m avito_monitor --config examples/config.json --db state/demo.sqlite --fixture examples/fixture.json pilot \
  --project demo-north --target 'https://docs.google.com/spreadsheets/d/demo-feed-north/edit#gid=20&range=A4' \
  --operation 96b70afd-b617-47ac-8913-839a5e7f102c
python3 -m avito_monitor --config examples/config.json --db state/demo.sqlite registry --project demo-north
python3 -m avito_monitor --config examples/config.json --db state/demo.sqlite inspect-feed \
  --xml examples/feed-id-missing.xml --old-id 000123 --title 'iPhone Example, белый'
```

`pilot` изменяет копию таблицы в памяти текущего процесса. Чтобы проверить запись на диск, передайте путь к новому файлу в `--save-fixture`. Реестр остаётся в SQLite. При `removal_confirmation: avito_status` передайте `--active-evidence` с наблюдением активности до очистки. Старый сценарий проверки XML доступен для диагностики.

## Локальная проверка XML

Модуль `avito_monitor.feed_preview` строит контрольные файлы по двум сохранённым снимкам листа. Снимок содержит JSON массив строк с полями `row`, `id`, `title` и `price`. Пустой технический ID передаётся как `null`. Сравнение допускает изменение только одного указанного `Id`.

```sh
python3 -m avito_monitor.feed_preview --before before.json --after cleared.json --row 3 --out test-xml
```

В варианте `omit-id` строка с ценой остаётся в XML даже при пустом `Id`. В варианте `strict` такая строка целиком исключается. Файлы содержат только `Id`, `Title` и `Price` и предназначены для локальной проверки. Результат этого сравнения сам по себе не подтверждает работу действующего генератора.

Сравнить контрольные XML можно командой:

```sh
python3 -m avito_monitor --config examples/config.json --db state/demo.sqlite compare-feed \
  --before examples/feed-before.xml --after examples/feed-id-missing.xml --old-id 000123
```

По умолчанию прежняя строка определяется по уникальному `Title`. Если этого поля недостаточно, передайте несколько `--match-field`, включая заголовок и устойчивые характеристики. Команда отличает исчезновение всей записи от пропажи тега `Id`. Если контрольная строка неоднозначна или изменились другие строки, вывод об исключении блокируется. Результат касается содержимого XML. Статус объявления проверяется отдельно.

## Подключение проекта

На настроенном сервере проект стандартного формата подключается двумя ссылками:

```sh
python3 -m avito_monitor --config config.local.json --db state/live.sqlite register \
  --project new-city --name 'Магазин' --city 'Город' --launch-date 2026-11-25 \
  --source 'https://docs.google.com/spreadsheets/d/PRICE_ID/edit' \
  --target 'https://docs.google.com/spreadsheets/d/AUTOLOAD_ID/edit' \
  --avito-profile AVITO_NEW_CITY
```

Служба подхватит проект в следующем цикле. Код сам находит товарные заголовки и блоки `Price`. На стандартных листах телефонов используются характеристики варианта, включая память, цвет и SIM. Уникальный точный заголовок используется для форматов, где прайс хранит `Title`. Дубли, неизвестные структуры и пропавшие строки попадают в диагностику. Чтобы подключить аккаунт Avito, передайте значения соответствующего профиля через защищённое окружение. Без `--avito-profile` работает сверка таблиц и отчёт.

Для постоянной работы с множеством проектов включите `"sync": {}` и настройте доступ к Drive API и Sheets API у серверной учётной записи. Дата запуска берётся из даты фактического старта проекта. Сервис сам применяет к утренней сводке отсрочку в 10 календарных дней.

1. Установите адаптер Google Sheets командой `python3 -m pip install -r requirements-google.txt`. Настройте Application Default Credentials и включите Sheets API. Дайте выбранной учётной записи права читателя на два файла.
2. Скопируйте `examples/config.json` в `config.local.json`. Укажите ID файлов или идентификатор существующего проекта из реестра мониторинга цен. Для реестра задайте `price_monitor_registry` и укажите `price_monitor_id` в проекте. Подхватываются название и два ID документов. Даты и правила выкладки хранятся в настройках этого сервиса. Если действующий реестр содержит ключи доступа, оператор может передать отдельную выгрузку его полей `id`, `name`, `client_spreadsheet_id`, `autoload_spreadsheet_id`.
3. Для нестандартного формата можно задать явные правила `routes`. Укажите ID листов `gid`, строку технических заголовков с единицы, массивы `keys` в одинаковом порядке и заголовок `price` в прайсе. `first_col` и `last_col` задаются с нуля как полуоткрытый диапазон. Для одной пары файлов можно настроить несколько блоков на одном листе. Для разделения вариантов целевой лист можно ограничить через точные фильтры `where`. Через `category` задаётся одна категория, а через `category_field` и `categories` можно задать карту по одному из структурных полей.
4. Выставьте `mode: draft` и запустите `check --project ИД`. Проверьте `status --project ИД` и выборочно сопоставьте строки, включая дубли, пустые цены и варианты товара. Включите `monitoring` после сверки. Для временного исключения задайте `paused`.
5. Внесите согласованные `launch_date`, `report_exclude_days` и `report_timezone`. Реализация считает дату запуска первым календарным днём. Например, при старте 10 ноября и периоде 10 дней проект впервые появится в сводке 20 ноября. Эта граница влияет на сводку. Оперативные уведомления настраиваются отдельно от утреннего запуска.

Режим `check` выводит число совпавших позиций и диагностики. Код возврата 1 означает диагностику хотя бы одного проекта. `status` показывает детали, ссылки на строки, время текущей и последней полной проверки, открытые инциденты и проблемы доставки. `registry` возвращает сохранённое значение ID с типом ячейки, координатами и журналом операций. Вывод реестра содержит рабочие данные. Команда `trace --project ИД --cell ССЫЛКА` показывает причину результата для конкретной ячейки.

Добавьте `coverage_targets` со списком `gid`, `name` и `header_row` проверяемых целевых листов. В сводке будут видны заполненные строки, для которых нет настроенного правила. Для связи с Авито задайте `marketplace_field` и при необходимости `marketplace_header_row`. Например, заголовок «Номер объявления» может находиться в первой строке, а технический `Id` во второй.

Для пилота на доступных по ссылке копиях адаптер может читать XLSX-экспорт. Передайте `google_xlsx_exports` как таблицу соответствий `{ "ID_КНИГИ": { "ID_ЛИСТА": "Имя листа в XLSX" } }`. Google может сокращать названия листов при экспорте. Это режим отчётности на чтение. Для рабочих операций с `Id` используйте Sheets API.

## Расписание и Telegram

В пилоте используйте отдельную БД `state/live.sqlite` и оставьте `telegram_enabled: false`. Команда `report` покажет сводку по проектам с количеством позиций по категориям. Команда `report --details` покажет конкретные товары, ссылки на строки и сохранённые Id для ручного возврата. Если у проекта задан `details_url`, ссылка на реестр появится и в сводке.

После согласования общего чата и расписания задайте `telegram_enabled: true`. Передавайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` через окружение сервиса. Один запуск доставки отправляет в один chat ID. Первый рабочий срез по новой конфигурации собирает исходное состояние. В дальнейшем новые случаи выкладки и техническая диагностика попадают в очередь. `notify_removal` включает оперативные сообщения об открытых случаях снятия. Утренняя сводка показывает обе группы независимо от этой настройки.

- Для ручного цикла запускайте `check`, затем `deliver`. Если `check` вернул 1, диагностика готова к доставке.
- Для автоматического расписания заполните `schedule` по примеру из `docs/operations.md` и вызывайте `tick` раз в минуту. Команда опрашивает источники по настроенному интервалу и готовит одну сводку за день. Отдельная команда `dispatch` обрабатывает обе очереди. Её таймер запускается отдельно после подключения Telegram. Файлы `deploy/` служат примером настройки на Linux и автоматически не устанавливаются.
- В режиме `sync` команда `tick` обновляет базу из очереди изменений. `dispatch` собирает утреннюю сводку непосредственно из базы, фиксирует её перед отправкой и обрабатывает оперативные сообщения. Если сводка превышает лимит сообщения, бот отправляет пронумерованные части в тот же чат.
- В 08:00 в согласованной зоне планировщик запускает `report --commit-report`, затем `deliver --daily`. Повторный запуск для той же даты использует уже зафиксированный текст, части идут по порядку. Для диагностики доступны `deliver --daily YYYY-MM-DD` и `status`.
- При ответе Telegram 429 очередь соблюдает указанную задержку и делает до трёх попыток. При неизвестном результате запроса очередь сохраняет `UNCERTAIN`. Проверьте появление сообщения в чате перед любым ручным повтором.

## Хранение, обновление и откат

Храните конфигурацию, окружение и SQLite вне Git. Используйте один экземпляр сервиса и локальный постоянный диск. Для согласованных запусков планировщика используется файловая блокировка одной базы. Код возврата 2 при занятой блокировке позволяет планировщику повторить задачу позже.

Перед обновлением остановите новые запуски и сделайте резерв SQLite через SQLite Backup API или командой `sqlite3 state/live.sqlite ".backup 'state/live-backup.sqlite'"`. Скопируйте отдельно локальную конфигурацию без токенов. Запустите проверку на учебной паре, затем сухой отчёт по согласованным проектам. Для отката отключите задания мониторинга и верните предыдущий код с совместимой копией базы. Мониторинг цен и его планировщик обслуживаются отдельно.

Справка по интеграциям: [Google Sheets API](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/get), [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage).
